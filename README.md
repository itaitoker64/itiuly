# My Big Trip 🌏

אפליקציית תכנון הטיול המשותפת של איתי וטליה.

שני משתמשים, מסך התחברות משלהם, וכל התוכנית יושבת במסד נתונים אחד ב-Neon —
כל שינוי שאחד מהם עושה מופיע אצל השני תוך שניות, מכל מכשיר.

## מה יש באפליקציה

| לשונית | מה בפנים |
|---|---|
| 🏠 בית | ספירה לאחור, איפה נמצאים עכשיו, מצב התקציב, המשימות הדחופות והתראות |
| 🤝 ביחד | **השבועיים המשותפים בתאילנד** — 16 ימים שעה אחר שעה (146 שורות), המסלול והטיסות, מה כבר הוזמן, השוואת מלונות, תקציב מפוצל 2/3–1/3 ומידע שימושי |
| 🗺️ מפה | כל היעדים והמקומות השמורים על מפה אחת, עם הוספת נקודה בלחיצה |
| 🌍 מדינות | תאילנד, סרי לנקה, וייטנאם, פיליפינים — יעדים, צ׳ק-ליסט הכנה, טיסות, לינה ותקציב לכל מדינה |
| 📅 ציר זמן | כל המסלול לפי תאריכים |
| 🎒 עוד | צ׳ק-ליסט ראשי, רשימת ציוד, **רשימת קניות**, מקומות שמורים, הוצאות ומסמכים |

הפרק המשותף (🤝) נבנה מהקובץ של טליה: כל שורה ניתנת לסימון כבוצעה ולעריכה
(שעה, מחיר בבאט, סטטוס והערות), והתקציב מתחשב מחדש אוטומטית — כולל שער ההמרה,
הרזרבה והחלוקה בין השניים.

## העלאה ל-Vercel

### 1. מסד נתונים ב-Neon

ב-Vercel, בפרויקט: **Storage → Create Database → Neon**. Vercel מגדיר את
`DATABASE_URL` לבד. אפשר גם ליצור פרויקט ישירות ב-[neon.tech](https://neon.tech)
ולהעתיק את מחרוזת החיבור.

הטבלאות (`users`, `trip_state`) נוצרות לבד בפעם הראשונה שנכנסים — אין מיגרציה להריץ.

### 2. משתני סביבה

ב-Vercel: **Settings → Environment Variables**. שלושה ערכים נוספים:

| משתנה | מה זה |
|---|---|
| `AUTH_SECRET` | מחרוזת אקראית לחתימת עוגיית ההתחברות. ליצירה: `openssl rand -base64 32` |
| `ITAI_PASSWORD` | הסיסמה של איתי |
| `TALIA_PASSWORD` | הסיסמה של טליה |

הסיסמאות נשמרות במסד הנתונים כ-hash (PBKDF2-SHA256) ולא כטקסט.
כדי לשנות סיסמה — משנים את משתנה הסביבה ועושים Redeploy; הכניסה הבאה תעדכן את ה-hash.

### 3. דיפלוי

מחברים את הריפו ל-Vercel ולוחצים Deploy. זהו — אין הגדרות בנייה מיוחדות.

## פיתוח מקומי

### עדכון KYN והוצאות

פרטי KYN עודכנו לפי התכתבות המחנה: 26–29 בנובמבר 2026, שני אנשים
בדירת Panoramic Sunset View A/C. נשלחה בקשה להתקדם, אך פרטי הבנק,
תשלום המקדמה ואישור ההזמנה הסופי עדיין ממתינים.
฿14,580 הוא אומדן של 3 × (฿3,800 + ฿660 + ฿400), ומקדמת 50% היא
฿7,290. יש לאשר את מספר ימי החיוב ואת כיסוי יום העזיבה מול החשבונית.
החבילה מסווגת כלינה; הארוחות והאימונים הכלולים אינם מתווספים שוב לתקציב.

מיגרציה לגרסה 6 משמרת שדות שנערכו ידנית וסימוני ביצוע. הוצאה קיימת
בשם KYN / Phoenix / Panoramic Sunset נשמרת ללא יצירת חבילה כפולה;
במקרה כזה יש לבדוק ידנית שהיתרה והתמחור משקפים את ההצעה החדשה.

בדיקת המיגרציה, תמחור החבילה וסינון ההוצאות:
`node scripts/check-kyn.cjs`.

### אומדן הטיול בשקלים

לשונית כסף → התקציב מציגה את כל 16 ימי הטיול המשותף ואת טיסת החזור של
איתי, ללא ההמשך של טליה. האומדן כולל מחירים מההזמנות הקיימות, אומדני
אוכל/תחבורה/פעילויות, הקצבות לנסיעה ורזרבה. אפשרויות מסומנות בנפרד ואינן
נכללות בסכום הראשי. ההמרה לפי השער השמור באפליקציה; זה אינו שער חי.

אפשר לערוך כל שורה בשקלים ולבחור אם לכלול אותה בסכום הראשי. עריכה כזאת
נשמרת כסכום שקלי קבוע ואינה מוסיפה חיוב לפנקס ההוצאות. המחירים מההזמנות
והארוחות/העברות הכלולות נספרים פעם אחת בלבד. מקור ותאריך בדיקה מופיעים
לצד אומדנים המבוססים על מחירון ספק; שאר הטווחים הם הקצבות תכנון.

בדיקות סכומים, היקף המסלול, מיגרציה ושימור עריכות:
`node scripts/check-estimates.cjs`.

### רשימת הקניות

רשימת הציוד נולדה כשכל פריט מסומן "לקנות", כך שהיא אמרה לקנות דרכון, טלפון
וגרביים. עכשיו רק מה שבאמת קונים מסומן כך, עם מקום קנייה ומחיר; כל השאר מסומן
כמשהו שכבר יש בבית. פריטים שאינם קנייה ואינם רכוש — TDAC, צילום דרכון, מזומן
חירום — נשארים פתוחים ברשימת הציוד ואינם נכנסים לרשימת הקניות.

לשונית עוד → קניות מציגה רק את מה שצריך לקנות, מחולק לפי מקום: בארץ לפני
הטיסה (מה שדורש התאמה אישית, מה שלא נמכר בתאילנד, ומה שצריך ביד בנחיתה)
ובתאילנד (ציוד מואיי תאי, שעולה שם כשליש, וכל הנוזלים). לכל קבוצה סכום
משלה, ופריטי רשות מוצגים בנפרד ואינם נספרים.

הרשימה בנויה לשימוש בזמן אמת, כשעומדים בחנות:

* לחיצה על ○ — או החלקה של השורה לצד — מסמנת שנקנה, עם רטט ואנימציה.
  מופיע טוסט ביטול לשבע שניות, כי לחיצה בטעות לא אמורה למחוק פריט בלי דרך חזרה.
* לחיצה על המחיר פותחת שדה במקום. לפריט שעוד לא נקנה זה תיקון האומדן;
  לפריט שכבר נקנה זה מה ששולם בפועל, והאומדן המקורי נשאר מוצג לצדו.
* סרגל התקדמות למעלה, עם מה שנשאר לקנות ומה שכבר יצא.
* שבבי סינון: הכול / בארץ / שם.
* מה שנקנה מתקפל לשורה אחת וניתן לפתיחה, כולל ביטול סימון.
* כפתור ＋ מוסיף פריט ישירות לרשימת הקניות, עם מקום ומחיר.

הסכום הזה אינו נכנס לפנקס ההוצאות — הפנקס סופר את מה שקורה בטיול עצמו.

הידע יושב ב-`SHOPPING` ו-`PACKING_TASKS` ב-`public/trip-app.js`. מיגרציה
לגרסה 10 מחילה אותו גם על מסמך שנשמר קודם, בלי לדרוס פריטים שנערכו ידנית.

בדיקת החלוקה, המחירים, הסכומים, התצוגה והמיגרציה:
`node scripts/check-shopping.cjs`.

```bash
npm install
cp .env.example .env.local     # ממלאים את הערכים
npm run dev                    # http://localhost:3000
```

`DATABASE_URL` יכול להצביע על Neon או על Postgres מקומי — הקוד בוחר את הדרייבר לפי הכתובת.

## עבודה בלי רשת

האפליקציה נפתחת גם בלי קליטה — על סירה, בקאו סוק, באי. השלד והתמונות נשמרים
ב-Service Worker, והתוכנית עצמה נשמרת עותק מקומי בדפדפן. שינוי שנעשה בלי רשת
נשמר במכשיר ועולה לשרת ברגע שהקליטה חוזרת; החיווי למעלה אומר *אין חיבור — נשמר
במכשיר*. אפשר להוסיף את האתר למסך הבית (manifest) והוא ייפתח כאפליקציה.

## מסמכים

לשונית עוד → מסמכים מאפשרת להעלות צילום דרכון, פוליסת ביטוח ואישורי הזמנה.
הקבצים נשמרים בטבלה `trip_files` באותו מסד נתונים, מוגשים רק למי שמחובר,
ומוגבלים לתמונות ו-PDF עד 6MB.

## גיבוי ושחזור

כל כתיבה נשמרת גם ב-`trip_state_history`, ו-30 הגרסאות האחרונות נשמרות.
לשחזור ידני:

```sql
UPDATE trip_state SET data = (
  SELECT data FROM trip_state_history WHERE state_id='trip' AND version=<מספר>
), version = version + 1 WHERE id='trip';
```

## שניים באפליקציה בו-זמנית

* כשהשני נמצא בפנים מופיע למעלה *טליה כאן עכשיו*, והסנכרון מאיץ מ-8 שניות ל-3.
* לכל שורה במסלול יש שיחה קצרה — אפשר לכתוב "נראה לי שנוותר על זה" והשני יראה
  את זה על השורה עצמה, עם השם שלו. נשמר כמו כל שאר התוכנית.
* לחיצה על כרטיס פעילות מסמנת אותו כבוצע, עם רטט ואנימציה. קישורים וכפתורים
  שבתוך הכרטיס פועלים כרגיל.
* משיכה למטה בראש הרשימה מרעננת.
* עדכון מהשרת לא נכנס באמצע הקלדה, כדי שלא יימחק טקסט שנכתב.

## איך הסנכרון עובד

* כל התוכנית נשמרת כמסמך JSON אחד בטבלה `trip_state`, עם מספר גרסה.
* שמירה היא `PUT /api/state` עם הגרסה האחרונה שהדפדפן ראה. אם בינתיים הצד השני
  שמר — השרת **מאחד את שני השינויים** (מיזוג תלת-כיווני מול הגרסה שממנה התחלתם,
  שנשמרת בהיסטוריה): מי שנגע בשדה מנצח את מי שלא נגע בו, ורק כששניכם שיניתם את
  אותו שדה בדיוק הגרסה השמורה גוברת ומדווחת. בדיקה: `node scripts/check-merge.cjs`.
* כל 8 שניות (וגם ברגע שחוזרים לאפליקציה) הדפדפן בודק אם הגרסה בשרת השתנתה,
  ואם כן — טוען אותה ומראה הודעה קצרה מי עדכן.
* חיווי המצב מופיע למעלה: *מסונכרן · מי שמר אחרון*, *שומר…*, או *אין חיבור*.
* תאריכי הטיול נקבעים לפי שעון בנגקוק ולא לפי UTC, כדי ש״היום״ יהיה היום גם ב-05:00.
* למסך ההתחברות יש הגבלת קצב: שמונה ניסיונות שגויים לחשבון ברבע שעה.
